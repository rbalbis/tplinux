# Module 2 — Manipuler des fichiers
## 2.2 — Liens symboliques vs liens durs

**Commandes utilisées :**

`ln` — crée un lien. *Pourquoi ce nom : "link".*
- `ln -s cible lien` → lien SYMBOLIQUE, un raccourci vers un chemin ; si la cible disparaît, le lien casse.
- `ln cible lien` (sans `-s`) → lien DUR, un second nom pointant vers le même inode (la même donnée physique).

## Exercice

```bash
ln -s logs/app.log courant
ls -l courant
readlink -f courant

ln data/salaires.csv data/salaires-dur.csv
ls -i data/salaires.csv data/salaires-dur.csv
```

Supprimer la cible d'un lien symbolique le casse. Supprimer un des deux noms d'un lien dur ne perd rien — les données ne disparaissent que quand le DERNIER nom pointant vers l'inode est supprimé.

**Anecdote** : le concept de lien dur est antérieur au concept de "fichier" tel qu'on le pense intuitivement — sous Unix, un fichier n'est fondamentalement QUE des données + un inode ; le "nom" n'est qu'une étiquette optionnelle posée dessus, d'où la possibilité d'en avoir plusieurs.

**À retenir** : `ls -i` compare les inodes, `ls -l` (2e colonne) montre le compteur de liens.
