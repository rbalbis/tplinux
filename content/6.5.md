# Module 6 — Processus et système
## 6.5 — systemctl et journalctl (théorie)

**Commandes utilisées :**

`systemctl` — pilote les services gérés par systemd (le PID 1 sur la plupart des distributions modernes).
- `status|start|stop|restart|enable service`

`journalctl` — consulte les journaux collectés par systemd.
- `-u service -n 50` → 50 dernières lignes d'un service.
- `-f` → temps réel.

## Exercice

```bash
ps -p 1 -o comm=      # doit répondre "systemd" pour que ces commandes marchent
systemctl status ssh
journalctl -u ssh -n 50
```

**À vérifier avant tout** : ces commandes échouent sur un conteneur Docker, Cloud Shell, ou toute machine sans systemd en PID 1 — d'où le réflexe `ps -p 1 -o comm=` systématique.

**À retenir** : `systemctl status` donne l'ÉTAT, `journalctl -u` donne la CAUSE. Toujours les deux ensemble (approfondi au module 9).
