# Module 9 — Services et systemd
## 9.5 — Timers : la relève de cron

**Fichier utilisé :**

`.timer` — unité de déclenchement planifié, le remplaçant moderne de cron (module 8.6).

```ini
[Timer]
OnCalendar=Mon..Fri 07:00:00
Persistent=true      # rattrape l'exécution manquée si la machine était éteinte
RandomizedDelaySec=300
```

## Comparaison avec cron sur 4 points

Journalisation (timers → intégrée à journald ; cron → aucune, sortie perdue sauf redirection manuelle), dépendances entre unités (timers → oui, via `After=` ; cron → non), rattrapage après extinction (timers → `Persistent=true` ; cron → non, l'exécution manquée est juste perdue), test à la demande (timers → `systemctl start service.service` immédiat ; cron → attendre l'heure ou modifier temporairement l'expression).

## Exercice

```bash
systemctl list-timers --all
systemd-analyze calendar "Mon..Fri 07:00:00"
```

**À retenir** : garder `cron` malgré tout sur un système SANS systemd (conteneur minimal, vieux serveur) — les timers n'existent que si systemd est présent.
