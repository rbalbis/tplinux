# Module 4 — Permissions, partie 1
## 4.2 — r/w/x : le piège fichier vs répertoire

Sur un FICHIER : `r` = lire, `w` = modifier, `x` = exécuter.

Sur un RÉPERTOIRE, le sens change complètement : `r` = lister les noms (`ls`), `w` = créer/supprimer/renommer des entrées, `x` = TRAVERSER (entrer, `cd`, accéder à un chemin à l'intérieur).

## Exercice — le "dossier aveugle"

```bash
mkdir aveugle
echo secret > aveugle/f.txt
chmod 100 aveugle   # x seul
ls aveugle          # échoue : pas de r
cat aveugle/f.txt   # fonctionne : x permet la traversée si on connaît le nom

chmod 400 aveugle   # r seul
ls aveugle          # fonctionne cette fois
cat aveugle/f.txt   # échoue : plus de x, impossible d'entrer
```

**Conséquence pratique** : supprimer un fichier dépend du `w` du DOSSIER PARENT, pas des permissions du fichier lui-même — un fichier en `444` reste supprimable si on a `w` sur son dossier.

**À retenir** : la quasi-totalité des "permission denied" incompris viennent d'un `x` manquant sur un dossier du chemin.
