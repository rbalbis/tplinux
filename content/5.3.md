# Module 5 — Identités et bits spéciaux
## 5.3 — SUID

**Commande utilisée :**

`chmod u+s f` ou `chmod 4755 f` — pose le bit SUID. *Pourquoi ce nom : "SUID" = SUID = "Set User ID (upon execution)" — définir l'ID utilisateur à l'exécution.*

## Le mécanisme

Un programme avec SUID posé s'exécute TOUJOURS avec l'identité de son PROPRIÉTAIRE, peu importe qui le lance.

## L'exemple canonique : /usr/bin/passwd

```bash
ls -l /usr/bin/passwd
```
→ `-rwsr-xr-x root root` — le `s` remplace le `x` du propriétaire.

Quand `alice` change son mot de passe, il faut écrire dans `/etc/shadow` (réservé à root). Sans SUID, impossible. Avec SUID, le temps de l'exécution, `alice` "devient root" UNIQUEMENT pour ce programme précis.

## Exercice — audit de sécurité

```bash
find / -perm -4000 -type f 2>/dev/null
```

Un binaire SUID root inconnu dans `/tmp` ou `/home` est une alerte quasi certaine — signature classique d'un attaquant qui s'assure un accès root permanent après une première intrusion.

**À retenir** : `S` majuscule (sans `x`) = bit inopérant, presque toujours une erreur de `chmod`.
