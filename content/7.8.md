# Module 7 — Réseau
## 7.8 — SSH et permissions de clé

**Commandes utilisées :**

`ssh` — connexion sécurisée à distance. *Pourquoi ce nom : "Secure SHell" — conçu dans les années 90 pour remplacer `telnet`/`rlogin`, qui transmettaient les mots de passe EN CLAIR sur le réseau (une faille énorme, exploitée en masse à l'époque).*

`ssh-keygen` — génère une paire de clés.
- `-t ed25519` → type de clé moderne (remplace progressivement RSA).

## Exercice

```bash
ssh-keygen -t ed25519
ls -l ~/.ssh/
chmod 644 ~/.ssh/id_ed25519   # casse volontairement
ssh -i ~/.ssh/id_ed25519 user@hote
```

`ssh` REFUSE catégoriquement d'utiliser une clé privée en `644` : "UNPROTECTED PRIVATE KEY FILE". Une clé privée = l'équivalent numérique de ta signature — si d'autres utilisateurs peuvent la lire, ils peuvent usurper ton identité sur tous les serveurs où elle est autorisée.

**À retenir** : clé privée toujours en `600`, clé publique (`.pub`) en `644` (elle est faite pour être partagée). Lien direct avec le module 4.
