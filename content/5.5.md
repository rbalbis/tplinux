# Module 5 — Identités et bits spéciaux
## 5.5 — Sticky bit

**Commande utilisée :**

`chmod +t rep` ou `chmod 1777 rep` — pose le sticky bit. *Pourquoi ce nom "sticky" (collant) : anecdote historique — à l'origine sur les tout premiers Unix, ce bit servait à garder un PROGRAMME "collé" en mémoire après son exécution pour accélérer les lancements suivants (usage aujourd'hui obsolète). Le sens a complètement changé avec le temps pour devenir la protection contre suppression qu'on connaît sur les dossiers — mais le nom "collant" est resté.*

## Le mécanisme actuel

Dans un dossier accessible en écriture à tout le monde, SEULS le propriétaire du fichier, le propriétaire du dossier, ou root peuvent supprimer un fichier — même si tout le monde a techniquement `w` sur le dossier.

## L'exemple canonique : /tmp

```bash
ls -ld /tmp
```
→ `drwxrwxrwt` — le `t` final.

Sans sticky bit sur `/tmp` (accessible en écriture à tous), n'importe qui pourrait supprimer les fichiers temporaires de n'importe qui d'autre.

## Exercice

```bash
sudo -u alice touch /tmp/f-alice
sudo -u bob rm /tmp/f-alice   # doit échouer
```

**À retenir** : SGID = qui hérite (groupe), sticky = qui peut supprimer — deux problèmes différents, combinables (`3770` = les deux ensemble).
