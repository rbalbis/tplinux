# Module 9 — Services et systemd
## 9.2 — Déployer un service : compte dédié et unité

**Commandes utilisées :**

`useradd -r -s /usr/sbin/nologin user` — crée un COMPTE DE SERVICE. `-r` = compte système (pas un humain). `/usr/sbin/nologin` = refuse toute connexion interactive.

`systemctl daemon-reload` — recharge la configuration après TOUTE modification d'un fichier d'unité, sinon systemd travaille sur l'ancienne version.

`systemctl enable --now service` — active au boot ET démarre immédiatement.

## Structure d'une unité .service

```ini
[Unit]
After=network-online.target
[Service]
Type=exec
User=svc-app
ExecStart=/usr/bin/python3 -m http.server 8080
Restart=on-failure
[Install]
WantedBy=multi-user.target
```

## Exercice

```bash
sudo useradd -r -s /usr/sbin/nologin svc-miniapp
sudo systemctl daemon-reload
sudo systemctl enable --now miniapp
systemctl status miniapp
```

**À retenir** : un service ne tourne JAMAIS en root sans raison démontrée — compte dédié + `User=` dans l'unité.
