# Module 7 — Réseau
## 7.2 — ping et traceroute

**Commandes utilisées :**

`ping` — envoie des paquets ICMP, vérifie si une cible répond et mesure la latence. *Pourquoi ce nom : emprunté au sonar sous-marin — l'écho renvoyé par le "ping" acoustique confirme la présence d'un objet, exactement comme la réponse ICMP confirme qu'une machine est joignable.*
- `-c 4` → limite à 4 paquets.

`traceroute` — révèle les routeurs traversés jusqu'à une cible, saut par saut. *Pourquoi ce nom : littéralement "trace la route".*
- `-T` → utilise du TCP plutôt que l'UDP par défaut (passe mieux les pare-feux).
- `-p 443` → port TCP utilisé.

## Exercice

```bash
ping -c 4 1.1.1.1
ping -c 4 www.admin.ch
traceroute -T -p 443 www.admin.ch
```

Si `ping` sur IP réussit et sur nom échoue → le problème est le DNS, pas le réseau.

**Le mécanisme traceroute** : chaque paquet part avec un TTL croissant (1,2,3...) ; chaque routeur qui le reçoit décrémente le TTL, et à 0 répond avec une erreur ICMP contenant sa propre adresse — traceroute exploite ça pour faire "avouer" chaque intermédiaire.

**À retenir** : les `* * *` ne signifient pas forcément une panne — beaucoup de routeurs ignorent traceroute par politique tout en transmettant le vrai trafic normalement.
